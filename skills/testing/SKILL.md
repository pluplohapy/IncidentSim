# SKILL: testing

Что тестируем и чем — см. [`golangci.yml`](../golangci.yml) и CI. Здесь — как
разделить уровни, чтобы `make test` оставался быстрым, а поведение на реальном
движке проверялось отдельно и явно.

## Уровни

| Уровень | Что проверяет | Где лежит | Когда запускается |
|---------|---------------|-----------|-------------------|
| Unit | схема, загрузчик, интерфейсы, оркестратор, верификатор | `*_test.go` рядом с пакетом, `testdata/` для фикстур | `make test`, всегда |
| Компонентный | compose-adapter: рендер проекта, разбор логов и метрик | `internal/adapters/compose/render_test.go` | `make test`, всегда |
| Интеграционный | полный жизненный цикл на настоящем docker | `adapter_test.go` (`TestComposeFullLifecycle`) | `INCIDENTSIM_TEST_DOCKER=1 go test ./internal/adapters/compose/` |
| Приёмочный | демо-сценарий на задачи каталога | `scripts/demo.sh` | вручную и в CI-wiki |

## Правила

* **Фейк рантайма вместо Docker по умолчанию.** `runtime.FakeAdapter`
  запоминает вызовы и применённые патчи, поэтому тест проверяет *контракт*
  (`Up → Apply → Reset`), а не демон. Настоящий движок — только там, где
  поведение движка и есть предмет теста.
* **Интеграционные тесты не молчат.** Тест без Docker вызывает `t.Skip` с
  инструкцией, как его включить. Молчаливо пропущенный тест — это тест, о
  котором никто не знает.
* **Один тест — один инвариант.** Если тест падает, должно быть понятно,
  какой инвариант нарушен, без чтения остального файла.
* **Негативный кейс обязателен.** Каждое новое поле манифеста — тест на
  отказ (см. `testdata/manifests/invalid/`). Каждый новый тип проверки — тест
  на missing field, а не только на pass.
* **Тест ведёт себя как участник.** Инъекция сбоя → проверка → дистрактор →
  проверка → фикс → проверка. Именно в такой последовательности ловятся
  баги, которые unit-тест не видит: например, что `compose restart` не
  перечитывает env.

## Тест «дистрактор не проходит quality»

Самый важный тест системы. Он не про адаптер, а про смысл двух шлюзов:

```
1. старт сессии, сбой активирован;
2. применить дистрактор (маскировку симптома);
3. verify: correctness == pass, quality == fail, verdict == fail;
4. применить настоящее решение;
5. verify: correctness == pass, quality == pass, verdict == pass.
```

На compose это делает [`scripts/demo.sh`](../scripts/demo.sh); на unit-уровне —
`TestVerifyGatesRunIndependently` в `internal/core/core_test.go`.

## Как проверерить скилл

Возьми последний коммит, тронувший `internal/core` или `internal/verifier`:
для каждого нового публичного поведения есть либо unit-тест, либо явный
`t.Skip` с причиной. Если нет — коммит не дописан.
